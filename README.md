# luckydraw-web

행사용 럭키드로우 추첨 프로그램입니다.

## 동시 추첨과 당첨자 명단

업로드 화면에서 참가자와 행사 배경 이미지를 등록합니다. 기본값은 `4명 동시`이며, 번호판은 가로로 배치됩니다. Enter 키로 선택한 개수의 사번이 동시에 돌아간 뒤 함께 확정됩니다. 엑셀 저장 버튼에 포커스가 남아 있어도 Enter는 다음 추첨을 시작합니다. 키를 길게 눌러도 추가 추첨을 시작하지 않습니다.

추첨 화면에서 **숫자키 1·2·3·4**를 누르면 번호판 개수가 즉시 바뀝니다. 숫자패드도 Num Lock이 켜져 있으면 사용할 수 있습니다. **F2**로 여는 운영자 설정에서는 이번 추첨의 상품명과 번호판 개수를 변경할 수 있습니다. 예를 들어 네 명을 추첨한 뒤 불참자가 한 명이면 숫자키 `1`을 누르고 Enter로 한 명을 추가 추첨합니다. 개수 변경은 기존 당첨 기록·남은 참가자·엑셀 명단을 초기화하지 않습니다. 추첨 중에는 개수를 바꿀 수 없고, 설정 메뉴의 입력란을 편집할 때는 숫자 단축키가 작동하지 않습니다. F2 또는 Esc로 메뉴를 닫을 수 있습니다.

화면 아래의 당첨자 명단과 저장 버튼은 표시하지 않습니다. 당첨 내역은 회차·상품명과 함께 내부에 누적하고 엑셀에 자동 저장합니다.

첫 당첨이 확정되면 **바탕화면의 `당첨자명단_1.xlsx`에 자동 저장**합니다. 이어서 추첨하면 같은 파일에 누적 결과를 반영합니다. 업로드 화면에서 새 행사를 시작하면 `당첨자명단_2.xlsx`, 그다음은 `_3.xlsx`로 구분하며, 기존 파일이 있으면 다음 번호를 사용합니다. 같은 행사의 저장 경로는 앱을 다시 실행해도 복구합니다. 개수만 바꿀 때는 저장하지 않습니다. 순번, 추첨 회차, 상품명, 당첨 번호, 추첨 일시가 추첨 순서대로 들어가며 사번의 앞자리 0도 보존합니다. 번호판 개수를 바꾸면 **그다음 당첨자 묶음 앞에 빈 줄 하나**를 넣어 구분합니다. 개수만 여러 번 바꾸고 추첨하지 않으면 기존 명단은 그대로 유지되며 빈 줄도 중복해서 넣지 않습니다.

설치형 앱은 **종료 전에 마지막 결과를 저장한 뒤 종료**합니다. 추첨 연출 도중 종료해도 이미 선택된 결과를 포함합니다. 업로드 화면으로 돌아갈 때도 마지막 명단 저장을 마친 뒤 새 행사를 시작합니다. 자동 저장 시 탐색기나 Finder 창을 띄우지 않으며, **Ctrl+S / ⌘S**로 별도 사본도 만들 수 있습니다. 저장 실패 시 명단을 초기화하거나 앱을 종료하지 않고 안내를 표시합니다.

Chrome·Edge 브라우저에서는 **참가자 등록 완료 후 추첨 화면으로 이동할 때** 자동 저장 위치를 한 번 선택합니다. 기본 위치는 바탕화면이며, 이후 선택한 파일을 계속 갱신합니다. 추첨 화면의 Enter는 저장 위치 선택창을 띄우지 않고 바로 룰렛을 시작합니다. 선택한 파일은 해당 브라우저의 IndexedDB에 기억해 업로드 화면으로 이동할 때도 마지막 결과를 저장합니다. 브라우저의 파일 저장 방식은 [Chrome 공식 안내](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)를 참고하세요. 이 저장 기능을 지원하지 않는 브라우저는 매 추첨 후 누적 명단을 다운로드하며, 저장 위치와 중복 파일 처리는 브라우저의 다운로드 설정을 따릅니다.

추첨 횟수에는 제한이 없습니다. 등록된 참가자를 모두 뽑으면 전체 명단을 다시 채워 계속 추첨하며, 한 번의 추첨 안에서는 같은 사번을 중복으로 뽑지 않습니다. 다음 회차를 채울 인원이 부족하면 아직 뽑히지 않은 참가자를 먼저 뽑고 새 순환에서 나머지를 뽑습니다. 같은 사번을 중복 등록해도 한 번만 등록됩니다. 등록된 전체 인원보다 동시에 뽑을 인원이 많을 때만 개수를 줄이도록 안내합니다. 기존 당첨 기록과 엑셀 누적 명단은 순환 후에도 유지합니다. F2에는 남은 인원 대신 등록된 참가자 수와 반복 추첨 안내를 표시합니다.

당첨 내역과 남은 참가자는 해당 브라우저 또는 설치형 앱의 로컬 저장소에 함께 저장됩니다. **추첨 화면**을 새로고침해도 명단과 개수 설정이 유지되고, 연출 도중 새로고침한 경우에도 선택된 당첨 결과를 복구해 자동 저장합니다. **업로드 화면(`upload.html`)을 다시 열면 마지막 명단을 엑셀로 저장한 뒤 이전 당첨 명단과 참가자를 초기화합니다.** 번호판은 다시 4개로 시작합니다. 기존 행사의 파일은 보존하며 새 행사 파일은 `_2`, `_3`처럼 번호를 올려 구분합니다. 사이트 데이터 삭제나 다른 PC·브라우저로 이동하면 데이터가 공유되지 않습니다.

백월 이미지는 브라우저의 IndexedDB(설치형 앱은 앱 내부 IndexedDB)에 보관하며 서버로 전송하지 않습니다. 같은 환경에서 다시 접속하면 유지되지만 다른 기기에서는 다시 등록해야 합니다.

`npm test`로 추첨·중복 방지·저장 복구를, `npm run self-test`로 실제 Electron 화면과 연출을 검증할 수 있습니다.

엑셀의 `사원번호` 또는 `사번` 열을 참가자 번호로 사용할 수 있습니다. 엑셀과 범위 입력 모두 숫자를 최대 6자리까지 받으며, 짧은 번호는 앞에 0을 붙여 등록하고 추첨 화면에 항상 6자리로 표시합니다. 예를 들어 `7`은 `000007`로 표시되고 `012345`는 그대로 표시됩니다.

참가자 등록 화면에서 PNG, JPG, WebP 행사 배경 이미지를 선택할 수 있습니다. 이미지는 브라우저나 외부 서버가 아니라 앱의 로컬 저장소에 보관되므로 인터넷 연결 없이 유지됩니다. 추첨 화면은 일반 모니터, 4K 디스플레이, 울트라와이드 행사장 화면 크기에 맞춰 번호판을 균일하게 확대·축소합니다. 앱은 항상 전체 화면으로 실행되며 `Esc` 키를 누르면 설정 메뉴가 열려 있는 경우 메뉴를 닫고, 그 외에는 종료됩니다.

설치형 앱에서 예시 엑셀은 운영체제의 `다운로드` 폴더, 행사별 `당첨자명단_1.xlsx`, `당첨자명단_2.xlsx`는 **바탕화면**에 저장됩니다. 같은 행사의 자동 저장 파일만 계속 갱신합니다. Ctrl+S / ⌘S로 만든 사본은 `당첨자명단.xlsx`, `당첨자명단 (2).xlsx`처럼 구분합니다.

## macOS 오프라인 앱 만들기

```sh
./build-macos-app.sh
```

빌드가 끝나면 `dist/LuckyDraw.app`을 더블클릭해 실행할 수 있습니다. Windows 버전과 동일한 Chromium 엔진과 동일한 HTML/CSS/JavaScript를 사용하므로 두 운영체제에서 UI가 동일하게 표시됩니다. 엑셀 처리와 축하 효과를 포함한 모든 파일이 앱 안에 들어 있어 실행 시 인터넷 연결이 필요하지 않습니다.

## Windows x64 오프라인 실행 파일 만들기

```sh
./build-windows-exe.sh
```

`dist/windows/LuckyDraw.exe`는 Chromium 런타임과 모든 화면 파일을 포함한 단일 실행 파일입니다. 별도 설치나 인터넷 연결 없이 Windows 10/11 x64에서 실행할 수 있으며 macOS 버전과 같은 UI를 사용합니다.
